# LATIMUS Prospecting

Use **Prospecting → Import CSV** with company/contact rows you deliberately selected. Files up to 10 MB,200 columns and50,000 total workspace prospect rows are bounded by a64 MiB plaintext vault capacity. Practical capacity depends on evidence volume;10,000-row measurements are in the benchmark evidence. Split unusually wide or evidence-heavy files. CSV exports retain original columns and append uniquely named enrichment fields; spreadsheet formula protection prefixes dangerous cells only in exports, leaving encrypted originals unchanged.

1. Review proposed mappings and sample values. Unmapped columns remain in every export. Save/reuse mapping templates when helpful; duplicate files are detected by binary SHA-256. UTF-8, BOM/UTF-16 and Windows-1252 fallback are supported with an encoding label.
2. Inspect normalized company/person/domain clues. Shared domains with conflicting company names and ambiguous identities route to review. A company grouping is a request-saving strategy, not proof of identity.
3. Start work in Enrichment Jobs. Portable/browser preview performs local processing and records extension_required where fresh network research is unavailable. Advanced Mode asks exact company-site permission. It checks public DNS and robots, then reads bounded public company pages with cookies omitted and abort/rate controls. Company-level research is reused for imported people; it never searches for unrelated raw leads.
4. Without supplied websites, optional Brave search ranks company candidates using name/address/phone/geography. Ambiguity remains unresolved. A newly discovered domain requires another explicit permission action: inspect the candidate then re-run selected rows. Company access is limited to100 domains per permission request; research smaller selected groups for wider files.
5. Inspect evidence before using contact output. Verified work email requires an actually observed individual address, a strong company association and person identity affinity. Generic company email is an alternative, never a verified individual. Input emails remain user-provided; candidate confidence does not establish mailbox deliverability. There is no email-pattern guessing, private phone discovery, SMTP probing or authenticated LinkedIn scraping.
6. Accept selected rows, then choose **Promote to CRM**. This creates or safely deduplicates contacts, preserves source rows and applies suppression. Review does not upgrade public verification. CSV selection does not require EOS; intelligence-generated opportunities retain their EOS 65/evidence gate. Draft outreach still needs exact-content human review and sends nothing externally.
7. Export all/filtered/selected rows through Full Fidelity, CRM Import, POC Review, Verified Contacts Only, Exceptions, Company Only or Custom profiles. All retain source columns. Exports are plaintext; workspace backups are encrypted. Export Partial Results works independently of job completion.

## Private search setup

In Advanced Mode, open Provider Settings, grant the Brave host, and choose **Import key securely**. Select an owner-held text file containing the key or a JSON file with braveApiKey/brave_api_key/api_key. The full-tab UI transfers a scoped file handle; only the extension background reads the credential and encrypts it using your workspace key. The UI shows configuration/test status, never the credential. A real provider test is required before a success timestamp appears. The key is not included in workspace backups; import it separately on another device. No search subscription is required for supplied website research.

## Recovery and limits

Pause/cancel aborts in-flight research and keeps committed row checkpoints. Resume/retry only unfinished or failed work; completed CRM links are idempotent. Fresh cache is scoped to the encrypted workspace; force refresh bypasses it. Failed zero-page permission/network responses are not cached as research. Caches are bounded to100 companies/2 MB; row evidence is retained until workspace capacity is reached.

Keep the full-tab app open and unlocked while work runs. Lock clears keys/capabilities. On reopen/unlock, queued/running work starts from saved row checkpoints. An uncommitted read-only request can repeat. Closing/suspending the browser is not a guarantee of continuous execution. In Portable file mode, export the encrypted workspace before closing.

Current crawling supports public company HTML, bounded same-company links, optional Brave company resolution, and public email/phone/profile observations. It does not scrape paid/authenticated services or crawl external people-search sites. DNS checks are best effort; unsupported opaque/cross-company redirects, protected sites, IPv6 special-use addresses, inaccessible robots and large responses fail visibly. Managed cloud Chromium blocks direct file and unpacked extension startup, so actual target-desktop Advanced acceptance remains an explicitly unverified release boundary. Fixture tests are not live-contact or provider success evidence.
