# 55-source master plan coverage

Source authority: the owner-supplied **THE CONSULT 7-Sector Data Source Master Plan**, prepared October 2026, all 15 pages read. The 55 source rows on pages 3–6 were transcribed directly from PDF table cells, preserving stable IDs, names, sector order, trigger language, field summaries, costs, check cadences, geography, automation/POC codes and workbook destinations. Line-wrapped words are joined; source descriptions are not replaced with guessed API schemas.

The original workbook uses construction PERMIT_LEADS and Permit Lead Score alongside cross-sector SIGNALS and EOS. The browser application keeps the domain distinction; source rows never silently populate CSV prospecting, CRM or qualified opportunities.

## Current operating boundary

- All 55 IDs INT-001–INT-055 are preserved. Sources can serve several sectors; no seven-database split is introduced.
- The owner elected to keep **property-only feeds disabled**: INT-015–INT-022. Their metadata remains visible; they must not be retrieved/imported automatically until re-enabled. Mixed construction/development/energy/business sources remain in scope.
- Exactly three plan rows map to existing native retrieval adapters: INT-001→TDLR, INT-024→USAspending and INT-041→FMCSA. Official service/native transport responses were tested; this does not establish extension acceptance, every trigger, comprehensive source coverage or current workspace freshness.
- Austin permits and Census CBP are supplemental adapters, **not replacements for any of these 55 plan rows**. Austin is not Dallas/Fort Worth. A Census aggregate is not a company event.
- USAspending’s implemented bounded prime-contract query does not implement the plan’s entire grant/subaward/growth scope. FMCSA baseline/comparison does not prove expansion or new authority. TDLR registrations are distinct from municipal permits.
- All other sources expose honest file-import or credential requirements. A source-plan H/API potential is not live adapter proof. No one should read 55 registered sources as 55 automatically connected services.

## Metadata interpretation

`MASTER_SOURCES` in `src/domain/sourceMaster.ts` is the machine-readable ledger. Government/regulatory/public-authority publishers receive source tier A under existing policy; particular claims still require source/evidence review. Source-plan **check cadence** is preserved separately from unknown actual update frequency. The plan’s 1–5 signal-strength field is not populated with invented ratings: it remains null, as do unmapped live dates, counters, revenue attribution, precise source-refresh periods and stages. Workspace source runs supply actual health/last success and evidence.

Deployment tiers explicitly named on page 15 are marked `explicit source-plan priority`. Remaining rows receive a disclosed `purpose-based implementation sequencing` classification based on opportunity creation, validation or market context; the registry does not pretend these inferred row assignments were quoted from the PDF. URLs are official public source entries/reference destinations. Where the exact current API/portal path is unverified, the notes say so; a reference link is not a functional fetch contract.

Automation codes: H=API/bulk/structured potential, M=export/searchable portal, L=mostly manual. POC codes: H=often identifies firm/contact, M=identifies company but needs enrichment, L=market/context. These preserve source-plan descriptions, not measured success rates.

## Unfinished acceptance

For each automated source, establish an official supported retrieval contract, exact schema/date semantics, access/terms, bounded request/response and rate behavior, cancellation, provenance, entity/event deduplication, source outages, actual browser/runtime support and live source evidence. Importing a file records an operator-supplied source snapshot; it does not prove the file was fetched from the official service or that every imported statement is true. Credentials are configured securely when a real method requires them; no missing API keys are fabricated.

A full trigger detector requires more than a registry row or API response. Keep Permit Lead Score, EOS and Prospect Contact Confidence separate. Source data cannot grant permissions, approve outreach, alter client scope or fabricate a POC. A 55-row count is a scope-preservation check, not functional completion.
